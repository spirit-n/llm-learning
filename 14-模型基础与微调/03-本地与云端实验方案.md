# 本地与云端微调实验方案

## 1. 先给结论

这章可以在本地开始，不需要一上来租云卡。

- **RTX 3050 Ti 笔记本：本地主力。** 官方规格为 4 GB GDDR6。适合验证 CUDA 环境，并用 125M～350M 模型跑通完整 LoRA 流程；约 0.5B～1B 模型可以尝试 4-bit QLoRA，但要缩短上下文、batch size 设为 1，并开启梯度累积和 gradient checkpointing。
- **GTX 1050 Ti：备用。** bitsandbytes 的 NF4/FP4 量化要求 Pascal 或更新架构，因此它在架构上可用；但显存和速度都紧张，只适合很小的 smoke test，不作为主力。
- **RX 5700 XT：不作为学习主线。** 它虽然通常有 8 GB 显存，但不在 AMD 当前 ROCm 官方支持的 Radeon GPU 列表中；尤其 Windows 下，PyTorch 官方安装路径主要面向 NVIDIA CUDA。社区方案可能跑通，但排查驱动和算子兼容的时间不可控。
- **云端 NVIDIA 24 GB：做进阶实验时再租。** 想做 3B/7B QLoRA、1024 以上上下文、重复实验或超参数对比时，优先 L4/A10 这类 24 GB 卡。16 GB T4 可作为预算方案，但更容易因模型、序列长度和优化器配置出现显存不足。

最省时间的路线是：**3050 Ti 本地跑通小模型闭环 → 复用同一份数据和脚本，在 24 GB 云卡上换成 3B/7B 模型 → 比较质量、耗时和显存。**

## 2. 本地先确认环境

在带 NVIDIA 显卡的机器上执行：

```powershell
nvidia-smi
python -c "import torch; print('torch:', torch.__version__); print('cuda:', torch.cuda.is_available()); print('gpu:', torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'none'); print('vram_gb:', round(torch.cuda.get_device_properties(0).total_memory / 1024**3, 1) if torch.cuda.is_available() else 0)"
```

只有 `cuda: True` 才开始训练。先以 PyTorch 官网针对当前驱动给出的安装命令为准，不要把 CUDA Toolkit、PyTorch CUDA wheel 和显卡驱动版本随意混装。

## 3. 本地实验范围

### 第一阶段：必须完成

使用 125M～350M 的 causal language model 和几十到几百条教学样本，完成：

1. 切分 train/validation/test，保存数据版本。
2. 训练前跑固定测试集，记录基线。
3. 用 PEFT LoRA 训练少量 step，观察 train/validation loss。
4. 保存 adapter，而不是复制整份基础模型。
5. 用同一测试集比较训练前后结果，并记录显存峰值、耗时和配置。

这个阶段的目标是理解完整工程闭环，不是追求模型能力。

### 第二阶段：可选挑战

用约 0.5B～1B 模型尝试 QLoRA：

```text
4-bit NF4
batch_size = 1
gradient_accumulation_steps = 8～32
sequence_length = 256 或 512
gradient_checkpointing = true
只训练 LoRA adapter
```

如果仍然 OOM，依次缩短序列、减小 LoRA rank、换更小模型；不要用 CPU offload 硬撑一个很慢且无法重复的实验。

## 4. 什么时候租云卡

满足任意一项就切到云端：

- 目标模型是 3B/7B，而不是只验证流程的小模型；
- 需要 1024～2048 的上下文；
- 需要固定 seed 重复 2～3 次或比较多组超参数；
- 本地一次实验超过数小时，影响日常使用；
- 需要稳定复现实验，而不是排查老显卡驱动。

云端优先选择 Linux、NVIDIA 驱动/CUDA 已配置的镜像。建议从 **24 GB L4/A10** 开始；只有在明确知道模型能够放入显存时才选择 16 GB T4。租卡前先准备好数据、配置和本地 smoke test，云端只做放大实验，避免按小时付费排查基础代码。

## 5. 这章的验收标准

无需训练一个“大”模型。能交付下面这些就足够支撑应用工程岗位的学习目标：

- 一份无数据泄漏的最小数据集；
- 一份可重复的 LoRA/QLoRA 配置；
- 基线与微调后的同集评测；
- loss、显存、耗时和失败记录；
- adapter、基础模型版本、seed 和回滚说明；
- 能解释为什么该任务选择微调，而不是 Prompt、RAG 或工具调用。
