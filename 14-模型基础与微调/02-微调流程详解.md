# 微调、LoRA 与实验流程

## 1. 先定义任务

明确输入、输出、成功指标和基线。若目标是更新知识、提供引用或按用户权限访问数据，优先 RAG/工具，不要直接微调。

适合微调的候选：稳定格式/风格、分类抽取、特定交互行为、小模型领域适配。

## 2. 数据

- 来源和许可明确，删除隐私与密钥。
- 去重、清洗错误标签、控制类别/长度分布。
- 按用户/文档/时间分组切 train/valid/test，避免相似样本泄漏。
- 保存数据版本和生成过程；合成数据要人工抽检。

## 3. SFT 与 LoRA

SFT 用监督样本调整模型行为。全参数微调更新所有权重，资源高；LoRA 冻结基础权重，在部分线性层加入低秩矩阵，只训练较少参数。QLoRA 进一步以量化基础模型降低显存，同时训练 LoRA adapter。

低参数量不代表数据、评测和部署成本可以忽略。

## 4. 最小实验顺序（P2）

1. 建立 prompt/RAG 无微调基线。
2. 选择可在本地/云资源承受的小模型和 500～数千条高质量样本。
3. 用 PEFT/LLaMA-Factory 跑小规模 LoRA，监控 train/validation loss。
4. 固定测试集比较质量、安全、格式、延迟和成本。
5. 检查灾难性遗忘、过拟合、敏感输出和对抗样本。
6. 保存 adapter、base model 版本、配置、seed 和日志。

## 5. 部署

决定 adapter 动态加载或合并权重，评估量化精度、吞吐、显存和回滚。灰度发布，不覆盖可回退的基线。

## 6. 面试不要夸大

若只做过最小 LoRA 实验，应明确规模、模型、数据和指标，不说“掌握大模型训练”。重点证明你理解任务定义、数据质量、泄漏、评测、上线和回滚闭环。

资料：[Hugging Face PEFT](https://huggingface.co/docs/peft/)、[LLaMA-Factory](https://github.com/hiyouga/LLaMA-Factory)。
