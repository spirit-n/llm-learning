# 手写一个受控工具调用循环

先不依赖 Agent 框架，理解运行时真正负责什么。

## 1. 工具契约

```python
from typing import Literal
from pydantic import BaseModel, Field

class MetricArgs(BaseModel):
    metric_name: str = Field(min_length=1, max_length=100)

class SqlArgs(BaseModel):
    sql: str = Field(min_length=1, max_length=10_000)
    max_rows: int = Field(default=100, ge=1, le=1000)

class ToolResult(BaseModel):
    status: Literal["ok", "error", "denied"]
    data: object | None = None
    error_code: str | None = None
    message: str | None = None
```

参数 schema 是模型可见的契约；权限、SQL 语义和成本限制属于执行前的运行时校验。

## 2. Registry 不只是函数表

每个工具保存：名称、描述、参数模型、执行函数、是否有副作用、所需权限、timeout、输出上限和版本。不要只写 `{"name": function}` 后把所有信息散落在 prompt。

## 2.1 微软课程补充：工具系统的六个构件

[Microsoft AI Agents 的 Tool Use 章节](https://github.com/microsoft/ai-agents-for-beginners/tree/main/04-tool-use) 将完整工具系统拆成多个相互配合的部分。结合本项目，可整理为：

1. **Tool Schema**：模型看得懂工具名称、用途、参数和返回含义。
2. **选择/路由**：决定什么时候允许模型选工具，什么时候走确定性流程。
3. **消息处理**：保留 tool call ID，把执行结果准确对应回原调用。
4. **集成层**：把本地函数、HTTP API、MCP 和数据库统一接入。
5. **错误与验证**：参数、权限、timeout、业务错误和输出都要校验。
6. **状态管理**：记录已经调用什么、结果是什么、是否重复和还剩多少预算。

只写一个 `@tool` 函数只完成了第 1/4 的一小部分。练习时给自己的实现画六层图，并指出每层的测试文件。

## 3. 伪代码

```python
MAX_STEPS = 6

for step in range(MAX_STEPS):
    response = model(messages, tool_schemas)

    if response.is_final_answer:
        return validate_final(response)

    for proposed_call in response.tool_calls:
        tool = registry.get(proposed_call.name)
        if tool is None:
            result = unknown_tool_error()
        else:
            args = tool.schema.model_validate(proposed_call.arguments)
            authorize(user, tool, args)
            result = execute_with_timeout(tool, args)
            result = truncate_and_redact(result)

        messages.append(as_tool_message(proposed_call.id, result))

raise MaxStepsExceeded()
```

真实实现还需要捕获 schema 错误、权限拒绝、timeout、幂等、取消和 trace。不要把完整异常堆栈原样反馈给模型。

## 4. SQL 工具特别安全项

1. parser/AST 验证单条只读语句。
2. 数据库账户本身只读；应用校验不是唯一防线。
3. 表/列级权限，强制 limit、timeout、扫描量限制。
4. 隐藏连接串、内部 IP、完整错误栈和敏感数据。
5. 记录谁、何时、为何、运行了什么规范化查询。

微软课程特别强调：应用层 SQL 检查之外，数据库身份本身也应只有只读角色。即使模型、parser 或业务代码出现漏洞，底层账户仍不能 `DROP/INSERT/UPDATE`。学习环境也使用独立测试库，不连接公司生产库。

## 5. 测试表

| 用例 | 期望 |
|---|---|
| 合法指标查询 | 正确选工具和参数 |
| 不存在的工具 | 返回受控错误，不执行 |
| 参数缺失/类型错 | schema 拒绝 |
| DROP/多语句/注释绕过 | SQL Guard 拒绝 |
| 工具超时 | 有限重试或降级 |
| 重复相同调用 | 检测并停止 |
| 输出 10 MB | 截断/摘要并保留引用 |
| 达到最大步骤 | 明确退出，不无限循环 |

## 6. 完成标准

先用 fake model 返回预设 tool calls，把运行时测试完整；再连接真实模型。否则模型的随机性会掩盖你自己的循环 bug。
