### 1. conda 环境与 Jupyter Kernel 有何区别？

**Conda 环境**：

- Conda 是一个跨平台的包和环境管理器，用于创建隔离的 Python 环境。
- 它管理整个环境，包括 Python 解释器、库和依赖项。
- 通过 `conda create -n env_name` 创建，使用 `conda activate env_name` 激活。
- 解决包版本冲突问题，允许同时维护多个项目环境。

**Jupyter Kernel**：

- Jupyter Kernel 是 Jupyter Notebook/Lab 中执行代码的后端程序。
- 负责运行代码并返回结果给前端界面。
- 可以是 Python、R、Julia 等不同语言的解释器实例。
- 是临时的，通常只在 Jupyter 会话期间存在。

**主要区别**：

1. **范围**：Conda 环境是完整的环境，包含解释器和所有依赖；Kernel 只是执行代码的解释器实例。
2. **持久性**：Conda 环境是持久的；Kernel 是临时的。
3. **关系**：一个 Conda 环境可以关联多个 Kernel，但一个 Kernel 通常只关联一个环境。

### 2. `python -m pip` 为什么比裸 `pip` 更稳妥？

**裸 `pip` 的问题**：

1. **Python 版本不匹配**：可能使用系统默认的 Python 解释器，而不是当前激活的虚拟环境中的 Python。
2. **PATH 不确定性**：系统 PATH 中可能存在多个 pip 版本，不确定使用的是哪个。
3. **环境不一致**：可能不会考虑当前激活的虚拟环境，导致包安装到错误位置。

**`python -m pip` 的优势**：

1. **明确性**：使用当前激活的 Python 解释器来运行 pip 模块，确保版本匹配。
2. **环境一致性**：无论在哪个虚拟环境中，都使用该环境中的 Python 解释器。
3. **可移植性**：在不同操作系统和平台上表现一致。
4. **避免 PATH 问题**：不依赖于系统 PATH 中的 pip 可执行文件。
5. **安全性**：减少意外安装到系统全局位置的风险。

### 3. `list`、`dict`、`set` 各适合什么？

**List（列表）**：

- **特点**：有序、可变、允许重复元素。
- **适合场景**：
  - 需要保持元素顺序的场景（如任务列表）。
  - 需要频繁添加或删除元素的场景。
  - 需要索引访问的场景。
  - 允许重复元素的场景。
- **示例**：`tasks = ["完成报告", "发送邮件", "参加会议"]`

**Dictionary（字典）**：

- **特点**：键值对存储、键唯一、查找速度快（O(1)）。
- **适合场景**：
  - 需要通过键快速查找值的场景（如配置信息）。
  - 需要描述元素间关系的场景（如学生姓名与成绩的映射）。
  - 需要高效更新值的场景（如缓存系统）。
- **示例**：`student_scores = {"Alice": 90, "Bob": 85}`

**Set（集合）**：

- **特点**：无序、不允许重复元素、查找速度快（O(1)）。
- **适合场景**：
  - 需要去除重复元素的场景。
  - 需要进行集合运算的场景（交集、并集、差集）。
  - 需要快速判断元素是否存在的场景。
- **示例**：`unique_numbers = {1, 2, 3, 4, 4, 5}`（自动去重）

### 4. Pydantic 与 type hint 有何区别？

**Type Hint（类型提示）**：

- **定义**：Python 3.5+引入的静态类型注解机制。
- **目的**：提高代码可读性、支持静态类型检查、帮助 IDE 提供更好的代码补全。
- **特点**：
  - 编译时/静态分析时使用，运行时通常被忽略。
  - 不强制执行类型检查，Python 解释器不会因类型不匹配而报错。
- **示例**：`def process_items(items: List[str]) -> Dict[str, int]:`

**Pydantic**：

- **定义**：一个基于 Python 类型提示的数据验证库。
- **目的**：确保数据符合指定的模式，提供数据序列化/反序列化功能。
- **特点**：
  - 运行时类型验证，在数据赋值或解析时强制执行。
  - 提供丰富的验证功能（类型检查、范围验证、正则表达式验证等）。
  - 自动将输入数据转换为正确的类型。
  - 提供详细的错误信息。
- **示例**：

  ```python
  from pydantic import BaseModel

  class User(BaseModel):
      name: str
      age: int
  ```

**主要区别**：

1. **执行时机**：Type hint 是静态的；Pydantic 是动态的，在运行时验证。
2. **强制性**：Type hint 不强制执行；Pydantic 强制执行数据验证。
3. **功能范围**：Type hint 仅用于类型标注；Pydantic 提供完整的数据验证功能。

### 5. 异步适合什么任务？为什么要限制并发？

**异步适合的任务**：

1. **I/O 密集型任务**：

   - 网络请求（HTTP API 调用、WebSocket 通信）
   - 数据库操作
   - 文件读写
   - 外部服务调用

2. **高并发场景**：

   - Web 服务器处理大量并发请求
   - 实时聊天应用
   - 流数据处理

3. **需要快速响应的用户界面**：

   - 桌面应用
   - Web 应用的前端
   - 移动应用

4. **需要处理大量并发连接**：
   - 聊天服务器
   - 实时游戏服务器

**为什么要限制并发**：

1. **资源耗尽**：

   - 内存：每个并发任务都需要内存，过多任务可能导致内存耗尽。
   - 文件描述符：每个网络连接或文件操作都需要文件描述符，系统有上限。

2. **系统负载过高**：

   - CPU 使用率：处理数据、编码解码等操作会消耗 CPU。
   - 磁盘 I/O：过多的并发文件操作可能导致磁盘 I/O 瓶颈。
   - 网络带宽：过多的网络请求可能导致网络拥塞。

3. **资源竞争**：

   - 共享资源（如数据库连接池）的竞争可能导致性能下降。
   - 锁竞争可能导致死锁或性能下降。

4. **稳定性问题**：

   - 资源耗尽可能导致系统崩溃或变得不稳定。
   - 错误处理变得复杂，难以追踪问题。

5. **延迟增加**：
   - 过多的并发可能导致任务排队时间增加，反而增加延迟。

**如何限制并发**：

- 使用信号量（Semaphore）
- 使用连接池
- 使用任务队列和限流器
- 使用专门的异步库（如 aiohttp、asyncpg）的并发控制功能
