# 非科班零基础学习方法

基础不好不等于学不会，但学习顺序必须更细。你不需要先补完四年计算机课程；遇到当前项目需要的基础，再补到“能继续前进”的程度。

## 1. 一条命令到底是什么

教程里的：

```powershell
conda activate llm-learning
python -m pip install pydantic
```

是让电脑执行动作的文本。需要在 **终端** 里运行，而不是写入 Python 文件或 Notebook Markdown。

Windows 常见终端：

- Anaconda Prompt：已经配置好 conda，初学阶段优先使用。
- PowerShell：Windows 通用终端，后续常用。
- VS Code Terminal：嵌在 VS Code 底部，本质仍是 PowerShell/其他 shell。

代码块左上角写 `python` 的内容通常放入 `.py` 或 Notebook Code Cell；写 `powershell` 的内容通常在终端执行；写 `text` 的内容只是示意，不能直接执行。

## 2. 不要一次复制十行命令

每次执行一行，观察：

1. 命令是否结束并重新出现提示符。
2. 是否有红字/Traceback/Error。
3. 输出路径是否属于预期环境。
4. 下一行命令依赖上一行成功吗？

例如创建环境失败后，不要继续执行 `conda activate` 和安装命令。否则后续错误会越来越乱。

## 3. 怎么读报错

Python traceback 看起来很长，先按顺序做：

1. 看最后一行：异常名称和简短原因，如 `ModuleNotFoundError`。
2. 从下往上找第一个属于自己项目的文件和行号。
3. 记录触发错误的输入和运行命令。
4. 用 `sys.executable` 确认解释器/Kernel。
5. 只改一个原因，再重新运行。

示例：

```text
ModuleNotFoundError: No module named 'pydantic'
```

它通常不是“代码语法错”，而是当前 Python 环境没有这个包，或 Notebook 选了另一个 Kernel。

## 4. 一个知识点的四遍学习法

以“函数”为例：

1. **看懂**：函数像一个有名字的小机器，接收输入，返回输出。
2. **照做**：运行教程里的 `add(a, b)`。
3. **修改**：改参数、加校验、故意传错类型。
4. **脱稿**：关闭教程，自己写一个计算指标的函数并解释。

只做到第 2 步很容易产生“看懂了但不会写”的错觉。

## 5. 英文官方文档怎么读

不要逐词翻译。先定位四类信息：

- Overview：这个工具解决什么问题。
- Quickstart/Get Started：最小可运行例子。
- Concepts：为什么这样设计。
- Reference/API：某个函数的精确参数，写代码时查。

使用浏览器翻译没问题，但保留核心英文词，例如 environment、kernel、tool、state，方便搜索报错。每次阅读设定具体问题：“如何注册 ipykernel？”而不是“今天读完全部 Jupyter 文档”。

## 6. 卡住多久应该求助

- 0～15 分钟：读错误、检查环境和命令。
- 15～30 分钟：查本仓库常见问题与官方文档。
- 30～45 分钟：整理最小复现并求助。

提问模板：

```text
目标：我想完成什么
环境：Windows、conda 环境名、Python 版本
执行命令：完整命令
实际结果：完整错误文本
预期结果：希望看到什么
已尝试：做过哪些检查
最小代码：能触发错误的最短代码
```

不要只发“报错了”和一张截断截图。

## 7. 做笔记的方法

每个概念只记五项：

```text
一句话定义
它解决的问题
一个最小例子
一个常见错误
我在项目中的使用位置
```

复制整页文档不是笔记。你要能在第二天不用原话解释。

## 8. 数学和算法补到什么程度

应用工程主线暂时需要：

- 初中代数与比例：理解成功率、平均值、成本。
- 向量直觉：一串数字表示文本特征，距离/相似度表示接近程度。
- 概率直觉：模型输出有不确定性，不等于固定规则。
- 基本指标：precision、recall、平均/P95。

矩阵推导、反向传播和训练优化可在第 8 周按兴趣补。不要因为暂时看不懂 Attention 公式就停止学习 RAG 应用。

## 9. 每天 4 小时怎么安排

- 30 分钟：复习昨天并口述。
- 60 分钟：读一小节教程/官方资料。
- 90 分钟：亲手编码和修改例子。
- 30 分钟：故意制造错误并定位。
- 30 分钟：记录结论与明日第一步。

连续看四小时视频通常效率很低。

## 10. 什么时候可以进入下一章

满足三个条件：

1. 最小例子可以从头运行。
2. 能用自己的话解释核心流程。
3. 遇到一个常见错误时知道从哪里查。

不要求全部记住。工程师也会查文档，能力在于知道该查什么、如何验证。
