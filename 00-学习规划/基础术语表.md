# 大模型应用基础术语表

遇到名词不懂先查这里。解释以建立直觉为主，后续章节会给更精确的定义。

## 电脑与 Python

### 文件、文件夹、路径

- 文件：保存内容的单位，如 `README.md`、`main.py`。
- 文件夹：组织文件的容器。
- 路径：文件的位置，如 `D:\workspace\llm-learning\README.md`。
- 绝对路径：从盘符开始的完整位置。
- 相对路径：相对当前工作目录的位置，如 `./data/test.json`。

“文件明明存在却找不到”经常是当前工作目录或相对路径不对。

### 终端、Shell、命令

终端是输入命令的窗口；Shell 是解释命令的程序，PowerShell 是 Windows 常用 Shell。`python app.py` 表示让 Python 运行 `app.py`。

### Python 解释器

真正读取并执行 Python 代码的程序 `python.exe`。电脑上可以有多个解释器，所以要用 `where python` 或 `sys.executable` 确认当前使用哪一个。

### 包、模块、库、依赖

- 模块：通常是一个可导入的 `.py` 文件。
- 包：组织多个模块的目录/发行单元。
- 库：提供某类能力的一组代码，日常常与包混用。
- 依赖：你的项目需要的其他包，如 FastAPI、Pydantic。

`pip install` 是安装包，`import` 是在代码中使用已经安装的模块。

### 环境（Environment）

一个隔离的 Python 和包集合。项目 A 与项目 B 可以使用不同版本，互不影响。conda 环境像每个项目自己的工具箱。

### Jupyter Kernel

Notebook 背后实际执行代码的 Python 进程。界面打开的是同一份 `.ipynb`，选不同 Kernel 就可能使用不同 Python/包。

## Web 与后端

### Client 与 Server

Client 发请求，Server 接收请求并返回响应。浏览器是 Client；FastAPI 程序通常是 Server。一个服务也可以作为 Client 调用模型 API。

### HTTP 与 API

HTTP 是网络通信规则之一；API 是程序对外提供的使用接口。比如 `POST /chat` 接收 JSON 问题并返回 JSON 答案。

### JSON

常见结构化文本格式：

```json
{"question": "什么是 RAG？", "top_k": 5}
```

它由对象、数组、字符串、数字、布尔值和 null 构成。JSON 格式正确不代表字段业务含义正确，所以需要 Pydantic 校验。

### 数据库、SQL、表

数据库保存和查询结构化数据；表由行和列组成；SQL 是操作关系型/分析型数据库的语言。Agent 生成 SQL 后必须经过安全校验，不能直接执行任意文本。

### 同步、异步、并发

- 同步：一个任务等待完成后再继续。
- 异步：等待网络/磁盘时允许程序处理其他工作。
- 并发：多个任务在一段时间内交错推进。

异步不等于无限并发，也不自动提高 CPU 计算速度。

## 大模型

### LLM / 大语言模型

根据上下文预测后续 token 的模型。它能生成流畅内容，但默认不是事实数据库，也不会自动访问你的文件和业务系统。

### Token

模型处理文本的基本片段，不等于一个汉字或一个英文单词。输入和输出 token 会占用上下文窗口、时间和费用。

### Prompt 与 Context

- Prompt：给模型的任务指令、问题、格式要求等。
- Context：模型这一次能看到的全部信息，包括 prompt、历史、检索结果、工具结果、系统规则和状态。

### Temperature

影响生成随机性的参数之一。低温度通常更稳定，但不会保证事实正确或消灭幻觉。

### Hallucination / 幻觉

模型生成看似合理但没有事实支持的内容。解决需要数据、检索、工具、验证和评测，不能只说“请不要幻觉”。

### Embedding 与向量

Embedding 把文本变成一串数字（向量），让语义相近的文本在向量空间中更接近。它用于语义检索，但对错误码、型号等精确匹配可能不如关键词搜索。

### RAG

Retrieval-Augmented Generation，检索增强生成。先从外部知识库找证据，再让模型基于证据回答。它包含数据解析、切分、索引、检索、排序、上下文和生成，不只是“接一个向量库”。

### Chunk

将长文档切成可检索的小块。太小可能缺上下文，太大可能噪声多、成本高，因此要用评测选择。

### BM25、Hybrid、RRF、Reranker

- BM25：传统关键词相关性算法，擅长精确词项。
- Hybrid Search：同时使用关键词和向量检索。
- RRF：按多路结果的排名进行融合。
- Reranker：对初步候选做更精细、更昂贵的重新排序。

## Agent

### Tool / Function Calling

模型根据任务提出要调用哪个工具以及参数；程序校验后真正执行。模型是“提出申请的人”，运行时是“审批并执行的人”。

### Agent

能在多步中观察状态、选择动作、调用工具、读取结果并继续的系统。Agent 不等于模型本身，模型外还需要状态、权限、执行、验证和停止条件。

### Workflow / Graph / State

- Workflow：预先设计的步骤和分支。
- Graph：用节点和边表达工作流。
- State：任务当前保存的信息，如问题、SQL、重试次数和结果。

### MCP

Model Context Protocol，标准化 AI 应用如何发现和连接外部工具、资源。它类似通用插座规范，但不会自动保证业务权限和工具安全。

### A2A

Agent2Agent，标准化独立 Agent 系统之间的发现、消息和任务协作。MCP 更偏 Agent 到工具，A2A 更偏 Agent 到 Agent。

### Context Engineering

设计模型在正确时刻看到哪些信息，怎样筛选、排序、压缩、隔离权限并控制 token，而不是单纯写更长 prompt。

### Harness Engineering

设计模型外的运行环境：任务规范、工具、权限、状态、执行、验证、trace、失败恢复和人工确认，使 Agent 可控和可审计。

### Trace 与 Evaluation

- Trace：记录一次任务每一步发生了什么，便于排错。
- Evaluation：用固定数据和标准测量系统质量。
- Golden set：人工整理的代表性测试问题、期望行为和证据集合。

## 常见指标

### Precision 与 Recall

以检索为例：

- Precision：找回来的内容中，有多少是真的相关。
- Recall：所有应该找回的相关内容中，实际找回了多少。

通俗说，Precision 关心“捞上来的鱼有多少是目标鱼”，Recall 关心“目标鱼总共有多少被捞上来”。

### P50 与 P95 延迟

把请求耗时排序，P50 是中间请求的耗时；P95 表示 95% 请求不超过这个时间。平均值可能掩盖少数特别慢的请求，因此生产系统常看 P95/P99。
