# 10 周求职倒排计划

这版适合**零基础大模型经验、但有后端/Java/数据系统基础**的人。相比 8 周版，它不降低最终门槛，而是把最容易卡住的内容拆开：Python/LLM 基础、RAG 评测、Agent 工程、MCP/生产化、面试表达分别留出缓冲。

## 适用判断

- 如果每周能投入 20～30 小时，10 周是更稳的主线；8 周更像冲刺版。
- 如果 Python、Docker、HTTP API、数据库都不熟，建议先用 1～2 周补工程基础，再进入本计划。
- 如果已经有 LLM/RAG 项目经验，可以压缩第 1、2 周，提前进入投递和项目打磨。

## 10 周后应交付什么

- 一个支持混合检索、重排、引用、拒答和评测的企业知识库 RAG。
- 一个带 SQL Guard、失败修复、trace、checkpoint/HITL 的指标查询 Agent。
- 一个只读 ClickHouse MCP Server，并能被 Agent 调用。
- 30～50 条 golden set、两轮可复现评测报告和失败案例复盘。
- 项目 README、架构图、演示视频、简历项目描述、系统设计答案和模拟面试录音复盘。

## 每周详细安排

### 第 1 周：工程环境与 Python 最小可用

**目标：** 先消除环境、命令行和 Python 心智负担，不让后续 RAG/Agent 被基础问题拖住。

- Day 1：安装 Anaconda/VS Code，创建 `llm-learning` 环境，安装 Jupyter/ipykernel。
- Day 2：运行 Python 入门 Notebook，掌握变量、容器、函数、模块。
- Day 3：Pydantic、异常、文件读写、JSON、`.env`。
- Day 4：FastAPI、请求/响应、状态码、OpenAPI 文档。
- Day 5：httpx、async/await、超时、重试、日志。
- Day 6：写 `/health`、`/echo`、`/chat-fake`，补 README 和自检脚本。

**验收：** 能解释环境、包、Kernel、API、JSON、日志分别解决什么问题。

### 第 2 周：LLM API、Prompt 与受控工具调用

- Day 1：真实模型最小连通性验证；无 Key 时用 fake model 保持主线推进。
- Day 2：消息角色、temperature、token、上下文窗口、结构化输出。
- Day 3：Prompt 实验：分类、抽取、改写、拒答。
- Day 4：Function Calling：计算器、指标定义、只读查询三个工具。
- Day 5：参数校验、超时、最大步数、工具白名单和审计日志。
- Day 6：用测试覆盖正常、非法参数、模型乱填参数、工具失败四类场景。

**验收：** README 能讲清“模型负责建议调用什么，程序负责校验与执行”。

### 第 3 周：RAG 基线

- Day 1：理解 ingest、index、retrieve、generate 四段链路。
- Day 2：解析 Markdown/PDF，保留标题、页码、来源、段落层级等元数据。
- Day 3：固定、递归、标题、语义 chunk 对照实验。
- Day 4：embedding、相似度、top-k、向量库；跑通 Qdrant。
- Day 5：生成带引用答案；实现“证据不足就拒答”。
- Day 6：人工制作 20 条问题、答案和证据 chunk。

**验收：** 能把一次错误归因到解析、切分、召回、排序、上下文或生成。

### 第 4 周：RAG 进阶与评测

- Day 1：BM25 与 dense retrieval 的互补性。
- Day 2：hybrid search、RRF、去重与 metadata filter。
- Day 3：cross-encoder/late-interaction reranker；记录召回率、延迟和成本。
- Day 4：RAGAS/人工评测；补齐 30～50 条 golden set。
- Day 5：对照 baseline、hybrid、hybrid+rerank，记录 Recall@k、MRR、faithfulness、P95 延迟。
- Day 6：完成项目一 README、架构图、失败案例和演示。

**验收：** 简历项目里必须出现真实指标，不写“显著提升”这种空话。

### 第 5 周：LangChain 与 LangGraph Agent v1

- Day 1：LangChain 当前核心抽象：model、message、tool、retriever、middleware、agent。
- Day 2：先手写有限步数 tool loop，再用 LangChain 重写并比较。
- Day 3：LangGraph 的 State、Node、Edge、Conditional Edge。
- Day 4：ToolNode、循环、错误路由、最大步数和确定性节点。
- Day 5：完成指标查询 Agent：schema 检索 → SQL 生成 → guard → 执行 → 校验 → 回答。
- Day 6：写 3 分钟 Agent 项目讲解稿。

**验收：** 能说明 Agent 与 workflow 的区别，以及为什么不用无限 `while True`。

### 第 6 周：Agent 工程化、Context 与 Skills

- Day 1：checkpoint、持久化、Human-in-the-loop、interrupt/resume。
- Day 2：Context 分层、选择、压缩、隔离、刷新和预算。
- Day 3：长工具输出摘要、历史裁剪、schema 按需检索。
- Day 4：按 Agent Skills 规范制作 `clickhouse-sql-review` skill。
- Day 5：AgentScope 做 0.5 天框架对照，不另起完整主线。
- Day 6：把 Agent v1 升级为可恢复、可观测、可解释的 v2。

**验收：** 能回答“为什么多数业务先用单 Agent，而不是多 Agent 辩论”。

### 第 7 周：MCP、Harness 与安全边界

- Day 1：MCP Host/Client/Server、tools/resources/prompts、能力协商。
- Day 2：实现 stdio MCP Server：list_tables、describe_table、run_readonly_sql。
- Day 3：实现 Streamable HTTP；加入鉴权、超时、白名单、limit、审计。
- Day 4：MCP 与 Function Calling/REST 的边界；A2A 只做概念卡。
- Day 5：Harness：task spec、context builder、tool registry、guard、executor、verifier、trace、recovery。
- Day 6：将 MCP 接入 LangGraph Agent，演练失败、重试、人工确认和恢复。

**验收：** SQL 工具必须默认只读、可审计、可限流、可拒绝危险输入。

### 第 8 周：生产化、评测与部署

- Day 1：组件级、轨迹级、端到端评测；tool call accuracy 与 goal success。
- Day 2：trace、结构化日志、request/task/tool_call ID。
- Day 3：Dockerfile、Compose、配置分层、健康检查、依赖锁定。
- Day 4：鉴权、限流、超时、重试、幂等、敏感信息脱敏。
- Day 5：缓存、并发、token/成本统计、模型降级。
- Day 6：部署项目，跑 eval v2，并整理优化前后数据。

**验收：** 陌生人能按 README 在 10～20 分钟内跑起核心 Demo 或理解不可运行原因。

### 第 9 周：作品集与系统设计

- Day 1：把 RAG、Agent、MCP 三个项目 README 统一成“问题、方案、指标、取舍、复现”。
- Day 2：录制 3～5 分钟演示视频，避免现场环境翻车。
- Day 3：复习 Transformer、attention、embedding、上下文窗口、decoder-only。
- Day 4：复习 SFT、LoRA/QLoRA、数据、评测、部署，以及 RAG/微调/工具调用选择。
- Day 5：准备 RAG/Agent/MCP/评测/部署系统设计白板题。
- Day 6：模拟面试，按录音修正表达过长、概念混淆、无数据支撑的问题。

**验收：** 每个项目都有 100 字简历版、3 分钟口述版、15 分钟深挖版。

### 第 10 周：金九银十冲刺与查缺补漏

- Day 1：根据 JD 高频缺口选择 1～2 个补强点，不再开新大坑。
- Day 2：投递与内推集中推进；按岗位定制简历关键词。
- Day 3：针对已约面岗位做公司/业务/技术栈准备。
- Day 4：二轮 mock：系统设计 + 项目深挖 + 代码/SQL 题。
- Day 5：复盘投递漏斗：回复率低改简历，面试低改表达和项目证据。
- Day 6：整理 offer/面试排期、下周补缺计划和版本化作品集。

**验收：** 面试官只看作品集首页，也能快速判断你会做 RAG、Agent、MCP、评测和部署。

## 对零基础大模型经验者的优化原则

1. **先主线后框架。** 先手写最小 tool loop 和 RAG，再上 LangChain/LangGraph，避免只会调框架 API。
2. **每两周必须有可展示产物。** 第 2 周 LLM 服务，第 4 周 RAG，第 6 周 Agent，第 8 周部署与评测，第 10 周作品集。
3. **不要追求技术名词全覆盖。** A2A、多模态、GraphRAG、微调、本地推理都按 JD 选修；P0 永远是 RAG、Agent、MCP、评测、部署。
4. **真实模型不是唯一阻塞点。** 没有 Key 或额度不足时，用 fake model 保持工具调用、检索、评测和工程链路推进。
5. **求职从第 5 周开始，不等学完。** 早投递不是为了马上拿 offer，而是用市场反馈校准简历和学习重点。
