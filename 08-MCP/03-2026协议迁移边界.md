# MCP：不要把协议版本与 SDK 版本混为一谈

核对日期：2026-10-04。当前课程继续保留 `mcp>=1.29,<2`，便于复现已有 Host/Server 安全测试；不在本轮强升到 v2。

| 维度 | 当前练习 | 新规范需要单独验证 |
|---|---|---|
| 会话 | 2025 协议 initialize / ClientSession | 2026-07-28 无初始化握手，每次请求携带版本/能力元数据，支持 server/discover |
| SDK | 1.x 的 FastMCP 与 ClientSession | 2.x 的 MCPServer / Client；版本兼容由 SDK 协调，不自行拼两套流程 |
| 长任务 | 本地受控调用与 timeout | Tasks 已移至扩展；不能因为 SDK 是 v2 就认定任务扩展已实现 |
| 交互输入 | 本工程没有完整交互 | MRTR 的 input_required / inputResponses，需拒绝、超时和重试测试 |
| 远程接入 | 本地安全与边界练习 | HTTPS、授权服务器发现、issuer/audience 校验、最小 scope、SSRF/重定向控制 |

依据：[协议变更](https://modelcontextprotocol.io/specification/2026-07-28/changelog)、[Python SDK v2 发布与迁移入口](https://github.com/modelcontextprotocol/python-sdk/releases/tag/v2.0.0)。发布页明确指出 v1 进入维护，并列出 v2.0.0 尚未包含 Tasks 扩展；规范、SDK 与服务器能力须分别确认。

学习次序：先完成当前 `tests/` 的目录过滤、调用鉴权与返回数据边界；再在独立环境迁移 SDK；最后补远程 Streamable HTTP/OAuth、交互输入和长任务。不要给本地学习服务直接开放公网，也不要把聊天模型 key 当作 MCP 的用户授权凭证。

迁移验收清单：记录协商出的协议版本 → 目录发现 → 正常调用 → 未授权拒绝 → 断连 → 版本不匹配 → 输入拒绝 → 副作用重试对账。协议取消/断连不是底层操作必然停止，授权或用户确认也不能由模型文字替代。
