## 新技术如何处理

### 采用：工程边界与可观测性

真实请求应保存 usage、结束原因和可定位的请求 ID，而不是只取字符串；模型/框架能力按端点验证。Chat Completions 仍作为现有兼容入口，Responses 单独实验，保留 typed output items 与工具 call ID，不全仓替换。[官方迁移指南](https://developers.openai.com/api/docs/guides/migrate-to-responses)

MCP 新规范改变了会话、协商和交互方式；当前 v1 工程加明确版本边界，迁移另开隔离实验。[规范变更](https://modelcontextprotocol.io/specification/2026-07-28/changelog)

OTel GenAI 约定仍在 Development，映射需带版本，不能把自由文本全量塞进 trace。[语义约定](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-spans.md)

### 试验：按需工具、原生压缩与可控执行

- 工具很多时，先比较“全量 schema”与“目录→搜索→加载”，同时评工具召回、权限泄露、额外发现成本。供应商原生 Tool Search 的支持取决于模型与 API，本仓库只有机制对照，不声称当前端点支持。[Tool Search](https://developers.openai.com/api/docs/guides/tools-tool-search)
- 原生 compaction 与本地结构化 checkpoint 不同；opaque compaction 项按接口要求保留，不自行拆解或当作可读摘要。实验以压缩后的任务恢复成功率为核心。[Compaction](https://developers.openai.com/api/docs/guides/compaction)
- Programmatic tool calling / sandbox 可以减少中间结果进入上下文，但仍需授权、网络/文件边界、资源预算和副作用审批；不是“让模型随便执行代码”。[官方说明](https://developers.openai.com/api/docs/guides/tools-programmatic-tool-calling)

### 观察：托管 Agent 平台

区分自行托管的 Agents SDK、托管运行时 Agents API 与直接编排 Responses；平台可代管一部分会话、工具、执行与观测，不等于替业务完成权限/幂等设计。当前先完成手写 loop / LangGraph，只有长任务运维负担明显时才比较托管方案的成本、恢复、数据边界和供应商锁定。[官方选型入口](https://developers.openai.com/api/docs/guides/agents)

多 Agent、Computer Use、实时语音、Agentic RL 等继续作为选修，不因新名词增加必修章节。
